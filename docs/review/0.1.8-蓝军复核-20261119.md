## 发布前必须处置 / 披露

1. **【P0 门禁·环境受限】确认目标宿主支持 `{prepend:true}`**：这是 P0 根因修复地基。静态实证充分（宿主 cordis `register` 仅 prepend 才 unshift，`dsh-compaction-basic/lib/index.js:880-902` 已用 prepend:true），但本次禁止重启宿主，**未做真机运行验证**。若目标宿主版本不支持→退化链尾→P0 根因复现。需用户重载后实测。
2. **【披露】hostOwns 判据与设计定稿的文字偏差**：设计 §5 定稿含 `hostRetryCount < policy.maxRetries` 第三项，实现（src/index.ts:1092-1095）只有 `mode==='normal' && retryableCodes.includes(code)`。当前"先问下游"架构下，能进 handleRequestError 的事件本身即宿主耗尽/码表外放行，缺该项**行为自洽**；文档称"判据藏进 next() 语义不重算"而代码仍算 hostOwns，属文档-实现表述偏差（已在设计文档补澄清）。
3. **【披露·设计取舍】"n 次重试"真实路径收窄**：真实事件 policy 恒有值→新分类恒启用。classifyFailure 对非标准码返回 unknown→直接 switch（0 次重试）；码表内瞬时码由宿主重试耗尽后直切；**仅"码表外且可判 transient"的错误才走 requestRetryMax 的 n 次重试**。这是设计 §5/§7 的保守策略，与"所有错误都重试 n 次"的朴素诉求有落差，非 bug。
